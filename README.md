# Решатель числовых ребусов

## Цель работы
Реализовать на языке C программу, которая решает числовые ребусы вида `SEND + MORE = MONEY`, где разным буквам соответствуют разные цифры, а первая цифра числа не равна нулю. Применить оптимизации разных типов (машинно-независимые, алгоритмические, эвристические), измерить их влияние на скорость и сделать выводы. В дополнительном задании расширить решатель на операции `-`, `\*`, `/`.

## Постановка и ограничения
- Ребус задаётся строкой `СЛОВО + СЛОВО + ... = СЛОВО` (от 2 до 7 слагаемых).
- Не более 10 различных букв (цифр всего 10), слова только из букв `A–Z`.
- Разным буквам соответствуют разные цифры.
- Первая буква любого слова не может быть нулём (включая слова из одной буквы).
- Если решения нет, программа печатает `no solution`.

## Структура репозитория
| Файл | Назначение |
|---|---|
| `rebus.c` | основное задание: четыре версии решателя (v0–v3) и бенчмарк |
| `rebus\_add.c` | дополнительное задание: операции `+ - \* /` |

## Сборка и запуск (основное задание)
```
gcc -O2 -Wall -Wextra -o rebus rebus.c
./rebus "SEND + MORE = MONEY"        # самая быстрая версия по умолчанию
./rebus "SEND + MORE = MONEY" 0      # выбор версии решателя (0, 1, 2, 3)
./rebus --bench                      # сравнение скорости версий
```

Пример вывода: `9567 + 1085 = 10652`.

## Ход работы
1. **Разбор строки.** Строка разбивается на слагаемые и результат, собирается множество уникальных букв, запоминаются «ведущие» буквы (им запрещён ноль). Для каждой буквы считается весовой коэффициент.

2. **v0 — базовый перебор.** Рекурсивно перебираются все размещения цифр по буквам. Для каждого полного размещения слова переводятся в числа, проверяются ведущие нули и сравнивается сумма.

3. **v1 — весовые коэффициенты** (машинно-независимая оптимизация). Вместо перевода слов в числа проверяется одна сумма Σ coef[i]·цифра[i] == 0.

4. **v2 — перебор с отсечениями** (алгоритмическая оптимизация и эвристики). Буквы перебираются по убыванию коэффициента. После каждого выбора оценивается, может ли оставшаяся часть свести сумму к нулю.

5. **v3 — решение «в столбик»** (алгоритмическая оптимизация). Колонки разбираются справа налево с переносом. Если колонка не сошлась, ветка сразу отсекается.

6. **Измерения.** Встроенный бенчмарк (./rebus --bench) усредняет время одного запуска.

## Результаты измерений
Время одного запуска в миллисекундах (`./rebus --bench`, `gcc -O2`):
```
puzzle (ms per run)                             v0          v1          v2          v3

BE + BE = MOO                               0.0758      0.0884      0.0006      0.0010

BIG + CAT = LION                           29.0000     23.4444      0.0005      0.0658

SEND + MORE = MONEY                        82.0000     65.5000      0.0008      0.1007

ELEVEN + NINE + FIVE + FIVE = THIRTY      186.0000    152.5000      0.0557      0.1060
```

Версия v2 с отсечениями оказалась самой быстрой на данных тестах. На сложных ребусах (10 букв) время решения сократилось с 186 мс до 0.05 мс (ускорение более чем в 3000 раз).

## Дополнительное задание: операции `+ - \* /`
Файл rebus\_ops.c. Сборка, запуск:
```
gcc -O2 -Wall -Wextra -o rebus\_ops rebus\_ops.c

./rebus\_ops "AB \* C = DEF"

./rebus\_ops --bench
```

Договорённости: стандартные приоритеты (сначала `\*` и `/` слева направо, затем `+` и `-`); деление только точное (без остатка), делитель не равен 0; ведущие нули запрещены; слово не длиннее 9 цифр.

Что сделано:
1. **v0** — полный перебор; равенство проверяется на каждом полном размещении цифр. Выражение вычисляется «слагаемое за слагаемым».

2. **v1** — оптимизированная версия:
- деление сводится к умножению (`A / B = C` превращается в `B \* C = A`);
- ведущим буквам ноль запрещается при выборе цифры;
- буквы перебираются от младших разрядов к старшим, и как только известны все буквы k младших разрядов, равенство проверяется по модулю 10^k (раннее отсечение).

Результаты замеров для доп. задания (время в миллисекундах):
```
puzzle (ms per run)                 v0          v1

AB \* C = DEF                    1.1292      0.0158

ABC / D = EF                    1.3741      0.0090

MONEY - SEND = MORE             3.2951      0.2716

A + B \* C = DE                  0.0590      0.0095

SEND + MORE = MONEY           125.0000      0.3155

ABC \* DE = FGHIJ               72.3333      0.2178
```

Оптимизация v1 (сведение деления к умножению и проверка по младшим разрядам) дала колоссальный прирост производительности. На ребусах с умножением и делением (`AB \* C = DEF`, `ABC / D = EF`) ускорение составило более чем в 70–150 раз. Даже на обычном сложении SEND + MORE = MONEY время сократилось с 125 мс до 0.3 мс.

## Вывод
1. Базовый перебор работает за факториальное время и не масштабируется.

2. **Машинно-независимые оптимизации** (весовые коэффициенты) дают лишь небольшой постоянный выигрыш, так как не уменьшают число перебираемых вариантов.

3. **Алгоритмические оптимизации** (отсечения, проверка по столбцам или по модулю 10^k) уменьшают число рассматриваемых вариантов и ускоряют решение в сотни и тысячи раз. Именно они определяют производительность.

4. Автоматические тесты на всех версиях подтверждают корректность решений.
